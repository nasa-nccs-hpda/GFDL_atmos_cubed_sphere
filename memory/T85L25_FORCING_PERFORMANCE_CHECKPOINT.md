# T85L25 Forcing Performance Checkpoint

## Goal

Evaluate forcing-module speedup at higher resolution.

Resolution:

```text
T85L25
```

Implementations compared:

- original Fortran Held-Suarez forcing;
- CPU C++ hybrid forcing;
- CUDA hybrid forcing.

Run configuration:

```text
resolution = T85
levels = 25
dt_atmos = 300 s
duration = 30 days
MPI ranks = 16
diagnostics = production Held-Suarez monthly diagnostics
forcing calls = 8640 per MPI rank
```

## Build Commands Used

All-Fortran baseline uses the stock Isca container build:

```bash
ls -lh ${GFDL_WORK}/codebase/_isca/build/held_suarez/held_suarez.x
```

CPU hybrid build:

```bash
USE_CUDA_HS_FORCE=0 ./run_compile_hybrid.sh
```

CUDA hybrid build:

```bash
USE_CUDA_HS_FORCE=1 ./run_compile_hybrid.sh
```

Important:

- CPU and CUDA hybrid builds both produce `held_suarez_hybrid.x`.
- For the sequential T85L25 run, the CUDA-enabled hybrid executable can run
  both `HS_FORCE_BACKEND=cpu` and `HS_FORCE_BACKEND=cuda`.


Validation command:

```bash
export GFDL_DATA=/explore/nobackup/people/jli30/SystemTesting/Isca/isca_data

python3 tests/validate_T85L25_forcing_outputs.py \
  --fortran-exp held_suarez_fortran_T85L25 \
  --cpu-exp held_suarez_hybrid_cpu_T85L25 \
  --cuda-exp held_suarez_hybrid_cuda_T85L25 \
  --filename atmos_monthly.nc \
  --fields temperature ucomp vcomp ps \
  --markdown-out tests/reports/T85L25_forcing_validation_report.md \
  --json-out tests/reports/T85L25_forcing_validation_report.json \
  2>&1 | tee logs/T85L25_forcing_validation.log
```

The validator compares:

- Fortran vs CPU hybrid;
- Fortran vs CUDA hybrid;
- CPU hybrid vs CUDA hybrid.

Metrics:

- max absolute error;
- RMSE;
- max pointwise relative error;
- relative L2 error;
- variable-by-variable summary.

It uses `temp` as the Held-Suarez temperature diagnostic when `temperature` is
not present and auto-detects forcing-related diagnostics if present.  It tries
Python/xarray NetCDF readers first and falls back to `ncdump` for requested
variables if Python NetCDF backends are unavailable.

## Speedups

MPP speedups:

| Comparison | Speedup |
|---|---:|
| CPU hybrid vs Fortran | 1.031x |
| CUDA hybrid vs Fortran | 0.644x |
| CUDA hybrid vs CPU hybrid | 0.625x |

Shell real speedups:

| Comparison | Speedup |
|---|---:|
| CPU hybrid vs Fortran | 1.032x |
| CUDA hybrid vs Fortran | 0.653x |
| CUDA hybrid vs CPU hybrid | 0.633x |

Estimated CPU forcing fraction of Fortran baseline:

```text
8.739947634 / 206.761356 = 4.23%
```

Theoretical maximum speedup if this entire forcing region became free:

```text
1 / (1 - 0.0423) = 1.044x
```

CPU observed speedup:

```text
1.031x
```

CPU efficiency relative to the possible Amdahl improvement:

```text
(1.031 - 1) / (1.044 - 1) = about 71%
```

CUDA observed speedup:

```text
0.644x
```

CUDA is a slowdown for this forcing-only POC.

## Lessons Learned

- T85L25 confirms that Held-Suarez forcing is still too small for major
  end-to-end speedup.
- CPU C++ hybrid forcing gives a small but measurable improvement.
- The measured CPU forcing fraction implies a hard Amdahl ceiling near 1.044x.
- The CUDA backend is useful for architecture validation, not performance in
  its current design.
- CUDA overhead dominates because each forcing call performs CPU/GPU transfer,
  local allocation/free, kernel launch, and synchronization while the rest of
  the model remains CPU-resident.
- For performance modernization, larger dynamics/advection/transform regions
  are better targets than the Held-Suarez forcing module.
